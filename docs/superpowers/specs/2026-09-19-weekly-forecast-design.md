# 週間予報タブ 設計書

- 日付: 2026-09-19
- ブランチ: `feat/weekly-forecast`
- 状態: 設計合意済み（実装前）

## 目的

エリアを選ぶと、そのエリアに属する各サーフポイントの7日分の予報（朝・昼・夕の波質スコア）を一覧できるようにする。
既存の「日付・時間帯を選んでランキング」機能はそのまま残し、タブで切り替える。

## スコープ

### やること

- 「ランキング / 週間予報」のタブ切替
- 週間予報: スポット別カードに 7日 × 朝昼夕 のスコア表と日ごとの波高
- セルをタップすると、その日・時間帯の詳細をカード内に展開
- 変換ロジックを `forecast.js` に分離し、ランキングと週間予報で共用する

### やらないこと

- 週間予報カードのスコア順ソート（比較はランキングタブの役割）
- 週間予報での潮位カーブ（詳細では満潮・干潮の時刻のみ）
- 1時間単位の表示、土日の色分け、選択状態の保存
- 取得方式の変更（複数地点をまとめて1回で取る方式は採用しない）

## 画面仕様

### タブ

- フォームの上に「ランキング」「週間予報」の切替を置く。初期表示は「ランキング」。
- 「週間予報」選択中は「日付」「時間帯」の入力欄を隠す。「エリア」と「チェック」ボタンは共通。
- 「チェック」ボタンと ↻ ボタンは、選択中のタブの取得を実行する。
- 結果の表示領域はタブごとに別にする（ランキング: `#results`、週間予報: `#weekly`）。タブを切り替えても、それぞれ前回の結果が残る。

### 週間予報の一覧

- 対象期間: 今日から6日後までの7日間。「今日」はブラウザのローカル日付（既存の `initDate` と同じ基準）。
- 見出し: `{エリア}の週間予報`、補足に `9/19(土)〜9/25(金) / {件数}件`。
- カードの並び順は `spots.json` の順（地理順）で固定する。

### スポットカード

- ヘッダー: スポット名、エリア名、週ベスト（例: `ベスト 水23 昼 72点`）。
- 本体: 7列（日）× 3行（朝・昼・夕）のスコア表と「波」の行。

```
       土19 日20 月21 火22 水23 木24 金25
  朝    62   58   31   45   70   66   52
  昼    60   49   28   51   72   60   48
  夕    41   33   25   55   68   57   40
  波   1.1  0.9  0.4  0.8  1.4  1.2  1.0
```

- 列見出しは `{曜日}{日}`（例: `土19`）。
- スコアのセルは点数帯で3段階に色分けする。満点は85点。

| 帯 | 条件 | クラス |
|---|---|---|
| 良 | 50点以上 | `good` |
| 普 | 30〜49点 | `ok` |
| 弱 | 30点未満 | `bad` |

- 「波」の行は、その日の朝・昼・夕の波高（`data.wave_height`）のうち最大値を小数1桁で表示する。3時間帯すべて欠けていれば `–`。
- 時間帯のデータが欠けているセルは `–` をグレーで表示し、タップできない。
- スマホ幅 375px でページが横スクロールしないこと。

### セルをタップしたときの詳細

- スコアのセルは `<button>` にする。`aria-label` は例 `9/23(水) 昼 72点`。
- タップすると、そのカードの表の下に詳細を展開する。
  - 見出し: `9/23(水) 昼（12-15時）`
  - 3項目: 波サイズ（波高・サイズ名・周期）、風向き（コンパス＋風速リング、オフショア等の判定、風向・風速）、うねりの向き。ランキングカードの `card-metrics` と同じ部品を使う。
  - その日の満潮・干潮の時刻（文字のみ）
  - 理由チップ（`reasonChips` と同じ判定）
- 同じセルをもう一度タップすると閉じる。別のセルをタップすると詳細を切り替える。展開できるのは1カードにつき1つ。
- 選択中のセルは強調表示し、`aria-pressed="true"` にする。

## データの流れ

### 取得（`app.js`）

`fetchSpotData(lat, lon, startDate, endDate)` に一般化する。

| 用途 | marine（波・潮位） | forecast（風） |
|---|---|---|
| ランキング | `date-1` 〜 `date+1`（変更前と同一） | `date` 〜 `date` |
| 週間予報 | `今日-1` 〜 `今日+7` | `今日` 〜 `今日+6` |

- marine の前後1日は、日付の境目付近の満潮・干潮を検出するため。今日+7 は Open-Meteo marine の提供範囲（約9日先まで）に収まる。
- ランキングの送信 URL は変更前と完全に同じにする。
- 週間予報は1スポットにつき marine と forecast の2リクエスト（ランキングと同じ）。スポット間は `Promise.allSettled` で並列に取得する。

### 変換（`forecast.js`、新規）

`scoring.js` と同じ UMD 形式にし、ブラウザでは `window.Forecast`、Node では `require("./forecast")` で使う。
`Scoring` への依存は、Node では `require("./scoring")`、ブラウザでは `root.Scoring` で解決する。

| 関数 / 定数 | 仕様 |
|---|---|
| `TIME_SLOTS` | `{ morning: [7, 10], afternoon: [12, 15], evening: [16, 19] }`。`app.js` から移す。開始時刻以上・終了時刻未満の時間を対象にする |
| `averageForWindow(hourly, slot, date)` | `app.js` から移す。`time` が `date` で始まり、時刻が時間帯内のサンプルを項目ごとに平均する（`null` は除外）。対象サンプルが0件なら `null` を返す（変更前はエラーを投げていた） |
| `slotConditions(marine, forecast, slot, date)` | marine・forecast それぞれの時間帯平均から `{ wind_dir, wind_speed, swell_dir, swell_period, wave_height }` を作る。うねり系が `null` なら合成波（`wave_*`）で代用する。どちらかの平均が `null`、または値が1つでも欠けていれば `null` |
| `weeklyForecast(marine, forecast, dates, bearing)` | `dates` の各日について `{ date, slots: { morning, afternoon, evening }, maxWaveHeight, tide }` を返す。各時間帯は `{ data, scores }`（`scores` は `Scoring.scoreSpot`）または `null`。`maxWaveHeight` は非 `null` の時間帯の `data.wave_height` の最大値（なければ `null`）。`tide` は `Scoring.tideEvents(marine.time, marine.sea_level_height_msl \|\| [], date)` |
| `bestSlot(days)` | 全セルのうち `scores.total` が最大のものを `{ date, slot, total }` で返す。同点なら日付が早い方、同じ日なら朝→昼→夕の順で先のもの。全セル `null` なら `null` |
| `scoreBand(total)` | 50以上 `"good"`、30以上 `"ok"`、それ未満 `"bad"` |

### 画面側（`app.js`）

- `rankSpot` は `Forecast.slotConditions` を使う形に書き換える。`null` のときはエラーを投げ、従来どおり「取得失敗」に入れる。画面表示は変更前と同じ。
- 追加するもの: タブ切替、週間予報の取得と描画、セルのタップ処理（`#weekly` でイベントをまとめて受ける）。
- 詳細の描画には既存の `metricIcon`、`jpDirection`、`windConditionLabel`、`waveIconClass`、`reasonChips`、`tideTimesLabel` をそのまま使う。
- 週間予報の画面側コードは `app.js` に置く（既存の部品を多く使い回すため）。

### `index.html` / `style.css`

- `index.html`: タブ、`#weekly` セクションを追加。`forecast.js` を `scoring.js` と `app.js` の間で読み込む。
- `style.css`: タブ、スコア表、点数帯の色、選択セル、詳細パネル。既存の配色・カードの見た目に合わせる。

## エラー処理

| 状況 | 表示 |
|---|---|
| スポットの取得が失敗（HTTP エラー・通信エラー） | そのスポットを「取得失敗: …」に列挙し、他のカードは表示 |
| 全スポットが失敗 | 「データを取得できませんでした。」 |
| 一部の時間帯だけデータが欠けている | そのセルを `–`（タップ不可） |
| 取得は成功したが7日すべてのセルが `null` | カードは出さず「取得失敗」に入れる |
| 取得中 | チェックボタンと ↻ を無効化（既存どおり） |

表示する文字列は `escapeHtml` を通す。

## テスト

### 自動テスト（`forecast.test.js`、`node --test`）

先に失敗するテストを書いてから実装する。テストデータはテスト内で1時間ごとの配列を組み立て、通信はしない。

- `averageForWindow`: 指定日・時間帯のサンプルだけを平均する／`null` を除外する／対象0件で `null`
- `slotConditions`: うねり欠損時に合成波で代用する／風が欠けていれば `null`
- `weeklyForecast`: 7日 × 3時間帯の構造／一部欠損は該当時間帯のみ `null`／スコアが `Scoring.scoreSpot` と一致／`maxWaveHeight` が最大値／潮汐イベントが日ごとに分かれる
- `bestSlot`: 最高点を返す／同点時の優先順位／全 `null` で `null`
- `scoreBand`: 85・50→`good`、49・30→`ok`、29・0→`bad`

既存の `scoring.test.js` もすべて通ること。

### 画面での確認

- ローカルサーバーで両タブを操作する。
- ランキングは変更前後で送信 URL とスコアが同じであることを確認する。
- Mac の Chrome をヘッドレスで起動し、375px 幅と PC 幅のスクリーンショットで表示崩れと横スクロールがないことを確認する（新しいパッケージは入れない）。
- セルのタップ操作は、最後にユーザーが手元のブラウザでも確認する。
